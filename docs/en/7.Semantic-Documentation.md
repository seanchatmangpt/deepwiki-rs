# Semantic Documentation

Litho can compile Rustdoc JSON into deterministic RDF instead of treating prose as the canonical documentation artifact.

## Canonical vocabulary and identity

The emitted graph uses the same `https://ggen.dev/ontology/semantic-documentation#` vocabulary as `ggen-marketplace/semantic-documentation-contract-pack`; Litho does not create a second documentation ontology. Repository and revision identity are mandatory. Supply them explicitly or through `GITHUB_REPOSITORY` and `GITHUB_SHA`; missing identity is refused rather than emitted as `UNKNOWN`.

```bash
cargo +nightly rustdoc -- --output-format json -Z unstable-options
cargo run -- semantic-docs \
  --rustdoc-json target/doc/<crate>.json \
  --repository owner/repo \
  --revision <exact-git-sha> \
  --output semantic-docs.trig
```

The output contains two named graphs:

- `urn:litho:graph:source:<revision>` — the revision-bound dataset plus Rust items, fully-qualified paths when Rustdoc supplies them, source spans, and intra-doc references. Rust items are explicit `SourceEvidence` with provenance back to the exact revision.
- `urn:litho:graph:documentation:<revision>` — Rustdoc Markdown as `DocumentationEvidence` / `DocFragment` linked to the item it documents.

All semantic-documentation entities are consequence-free evidence/projection objects and explicitly carry `grantsDoAuthority false` where the contract requires an authority fence.

A JSON receipt is written alongside the graph. It records the Rustdoc format version, exact repository/revision subject, evidence counts, authority ceiling (`none`), validation evidence, standing, and falsifiers.

## Open Ontologies validation

Pass the Open Ontologies binary to make RDF/ontology validation mandatory:

```bash
cargo run -- semantic-docs \
  --rustdoc-json target/doc/<crate>.json \
  --repository owner/repo \
  --revision <exact-git-sha> \
  --open-ontologies-bin /path/to/open-ontologies
```

Litho executes `open-ontologies validate <graph>`. A non-zero exit is fail-closed: the graph and receipt remain on disk as evidence and the command exits with an error.

This is **validation, not semantic admission**. Current Open Ontologies exposes SHACL as a separate `shacl <shapesfile>` / `onto_shacl` boundary. Therefore successful `validate` remains `PARTIAL_ALIVE`; Litho does not claim SHACL admission, registry publication, runtime execution, merge, or application authority from it.

The Marketplace contract pack ships portable SHACL shapes and repository-native ggen gates. A later closed-loop runner can bind the generated graph, those shapes, and Open Ontologies SHACL in one isolated validation session without changing the canonical vocabulary.

## Design invariant

`RDF is documentation; prose is a projection.`

The semantic command does not replace the existing Markdown/C4 pipeline. It establishes the canonical machine-readable substrate required for later SPARQL-generated C4, Diataxis, agent context, and conventional prose projections without making those projections sovereign.
